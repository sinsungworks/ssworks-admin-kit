# admin-kit Phase 0 — 정본 확정 · 확장점 목록 · A/B 배정

작성일: 2026-10-01
입력: kim5257-crm-v5, ssworks-axion-admin, ssworks-gise-home, hangang-home (+ kim5257-project-template)
방법: 관리자 공통 후보 파일 약 1,450개를 실제로 읽어 역할별로 대조. 상세 대조표는 부속 보고서 5편(§7)에 있다.
발행 방식 결정: npm 공개 스코프(`@ssworks/*`).

---

## 0. 한 줄 결론

네 프로젝트는 **crm-v5를 뿌리로 한 한 계보**이며(hangang은 파일마다 `ported from kim5257-crm-v5@…` 헤더로 수정 사유를 남겼고, gise는 hangang 일부를 재이식, axion은 템플릿 계열), 스택·저장 구조·권한 규칙(`'*'` 정확 일치 + AND/OR)이 전부 같다. 따라서 패키지화의 장애는 UI가 아니라 **프로토콜 차이**(응답 봉투, 쓰기 응답 형태, bigint/날짜 직렬화, 재인증 vs revision, fail-open vs fail-closed)다. 정본은 **프론트·백엔드 코어 인프라 = hangang, 인증 서비스·권한 순수함수 = gise, 도메인 모듈 골격·shared 스키마 = crm-v5**로 잡고, 차이는 §3의 옵션으로 흡수한다.

## 4. 프로토콜 결정 (2026-10-01 확정)

패키지 코드보다 먼저 확정해야 하는 계약. 각 항목은 4개 프로젝트가 2:2 또는 3:1로 갈려 있었다. 1·3·4·6은 사용자 결정, 나머지는 권장안 채택(이의 없으면 확정).

| #   | 항목                | 현재 분포                                                                 | **결정**                                                                                          | 비고                                                                                                                                                                                                    |
| --- | ------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 응답 봉투           | `{success,data}` crm/axion vs plain gise/hangang                          | **`{success:true, data}` 봉투 (사용자 결정)** — 오류는 `{success:false, code, message, details?}` | crm `response.schema.ts`(`createSuccessRespSchema`, `errorRespSchema`)가 정본. `createApiClient({envelope:'success-data'})` 기본값, plain은 옵션으로만. 예외 필터 응답 형태도 `success` 형으로          |
| 2   | 쓰기 응답           | `{item}` / `{success:true}` / `{}` / 204                                  | `data:{item}`(생성·수정), `data:{}`(삭제·move)                                                    | 프론트 갱신에 재조회 불필요                                                                                                                                                                             |
| 3   | `total`·날짜 직렬화 | bigint 문자열+Date(3) vs number+ISO(gise)                                 | **`"BigInt(n)"` 래퍼 + Date (사용자 결정)**                                                       | gise `bigint-json.ts`(B9 이스케이프)를 단일 구현으로 채택하고 프론트 `parseJSON` 리바이버·백엔드 `JsonTransformInterceptor`/replacer 모두 여기서 파생. `useServerTable`은 `total: bigint`를 그대로 받음 |
| 4   | 쓰기 보호           | 재인증(hangang) / revision(gise) / 없음(crm·axion)                        | **revision 기본 on, 재인증 옵션 (사용자 결정)**                                                   | roles·users·settings 코어 테이블에 `revision` 컬럼 포함. `useWriteFlow({revision:true, reauth:false})` 기본                                                                                             |
| 5   | 권한 가드 기본      | fail-open(crm·axion) vs fail-closed(gise·hangang)                         | fail-closed 기본, `failClosed:false` 과도기                                                       | hangang 주석: 상류 22곳 데코레이터 0건 사고                                                                                                                                                             |
| 6   | 인증 정책           | 평문 연장(crm·axion) vs 해시 회전(gise·hangang)                           | **해시 저장 + 회전 (사용자 결정)**, 유예창은 옵션                                                 | 기존 crm/axion 전환 시 `sessions` ALTER + 전 세션 재로그인                                                                                                                                              |
| 7   | 에러 코드 명명      | `ERR_COMMON_*`(3) vs `ERR_*`(gise)                                        | `ERR_COMMON_*`                                                                                    | 3:1                                                                                                                                                                                                     |
| 8   | 라우트 prefix       | `users` vs `admin/users`                                                  | `admin/` (옵션)                                                                                   | 관리자 패키지 목적                                                                                                                                                                                      |
| 9   | 권한 카탈로그 형태  | 리소스×read/write/delete(hangang) vs 카테고리별 액션 가변(crm/axion/gise) | 카탈로그 객체 주입(axion 형) — hangang 형은 그 특수 경우                                          | PermissionMatrix가 4곳 수용                                                                                                                                                                             |

결정 1·3의 파급: 정본이 hangang인 API 클라이언트·스토어·표 composable은 봉투 벗기기와 bigint 리바이버를 **기본 경로**로 두어야 한다(hangang은 둘 다 없는 쪽이었음). 반대로 crm/axion 기존 프로젝트의 전환 비용은 줄어든다.
